# Chat 纯前端制品

[构建工作流](../.github/workflows/build-release-bundle.yml) 只在 Chat 仓库的 `main` 上手动触发。它读取固定的 Open WebUI `v0.12.5` 提交、核原版依赖锁，使用 Node `22.14.0` 和 Python `3.12`，复用统一前端入口构建。制品链固定十层：既有八层，随后追加报错指引与模型能力对齐。旧构建入口的八层默认值不变。纯前端模式只应用浏览器源码补丁，不改构建源的后端文件，也不下载或替换运行镜像里的 Pyodide。

工作流只交付 GitHub Actions 制品，不写 GitHub Release、镜像仓库或生产环境。现有个人连接、Tavern、授权恢复的发布、启用、回退入口不消费这个制品，也没有改动。新制品本身没有生产部署或回退入口。

## 制品和校验

从同一次成功运行下载 `chat-frontend-<Chat 提交>-<run ID>-<attempt>`，解包后的根目录只有：

```text
frontend-build/
frontend-build-manifest.json
```

- **资产与清单**：工作流只读校验后直接上传统一构建的原输出，不复制或重写字节。清单记录上游提交、有序叠加层和每个公开文件的 SHA-256。校验拒绝额外文件、缺项、链接、路径穿越、私有 source map、Pyodide、后端、环境文件和密钥。品牌说明和许可证仍在公开资产中；不上传 Dockerfile、数据库、源码或 `frontend-debug/`。
- **来源**：以已核对的 Actions 运行、提交和工作流摘要里的制品 ID、归档 SHA-256 为准，不另设包内回执。下载后先核可信归档，再在无生产凭据的隔离目录解包。用对应的已审 Chat 源码复核两项公开输出：

  ```powershell
  node deploy/build-chat-frontend.mjs --verify-public '<已解包制品目录>'
  ```

## 限制与恢复

- Actions 制品保留 **14 天**，过期后不能把旧包当新提交的交付。工作流总时限 **40 分钟**，依赖安装最多 **12 分钟**；前端构建沿用单步 **20 分钟**限制和 **8 GiB** Node 堆。失败、超时或校验不一致不上传；修正输入后重跑，生成独立的重试制品，不覆盖原版本。
- 制品最多 **12,000** 个公开文件、**512 MiB** 公开字节，单个文件最多 **128 MiB**，清单最多 **2 MiB**。超限直接拒绝，不截断。不把本地部分输出当成候选；本地再次构建时使用新目录。
- 消费接线另审：用清单对应的已审叠加层核对后端前置，只叠加到包含对应后端的运行基线。不能直接用官方原版镜像上线，也不能把制品传给旧个人连接发布。待单独批准后再验账号恢复、个人连接、既有静态文件与 Pyodide、继承的旧资源可见性和前端回退。构建及逐文件校验不代替真实登录或模型调用验收。
