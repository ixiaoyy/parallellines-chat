# Chat 前端产物本地缓存

本能力只减少同一准备源码的重复生产构建，不改变 Chat 的运行行为、界面、身份链或模型配置。
它不是依赖下载缓存，也不是通用构建平台；未设置 `--cache-dir` 时继续原构建路径，不读取缓存。

## 用法和兼容

从仓库根目录执行，`SOURCE` 为准备好的固定 Open WebUI 源码，`OUT` 必须是不存在的新目录：

```sh
node deploy/build-performance-frontend.mjs SOURCE OUT
node deploy/build-performance-frontend.mjs SOURCE OUT bootstrap
node deploy/build-performance-frontend.mjs SOURCE OUT --cache-dir CACHE
node deploy/build-performance-frontend.mjs SOURCE OUT bootstrap --cache-dir CACHE
```

前两条旧用法及其源码、锁文件、错误和输出保护合同保留。`bootstrap` 与默认性能补丁模式分别建身份，
不能互相命中；原补丁顺序仍须通过入口检查。缓存模式要求 `OUT` 在准备源码目录之外。

推荐将缓存放在用户可控的 ignored `.build` 子目录，不与准备源码和发布输出重叠。
工具也拒绝缓存放入实际 `node_modules` 安装树、`openwebui-profile-overlay`、`identity-bridge`
或 `main-profile-overlay` 三个已知 Docker 构建上下文中，包含 junction/symlink 解析后的真实位置。
缓存只适用于可信的本地用户目录；POSIX 下目录限制为 `0700`，Windows 应使用仅当前用户可访问的目录，
不把权限位当作 Windows ACL 隔离证明。

## 哪些输入决定命中

`deploy/frontend-cache-input-policy.json` 固定已审核配方与范围：

- `src`、`static`、`scripts`、`crypto/encryption` 的真实文件字节、路径与执行位。
  仅 `crypto/encryption/target` 按已检查的加密产物校验脚本作为生成输出排除；
  `src/static/scripts` 中的 `target` 目录仍计入。真正使用的是已提交的加密 vendor 文件，仍完整校验。
- 固定的 Vite、Svelte、PostCSS、Tailwind、TypeScript、SPA 路由选项、版本及锁文件配置。
  根 `.npmrc` 不读取：本入口直接运行 Node，不运行 npm；安装效果由实际依赖文件绑定。
- 实际安装的全部依赖文件及 Node 二进制、版本、平台/架构；仅安装根的派生工具缓存排除。
  不以锁文件、包版本号或文件时间代替实际字节身份，不信任上次元数据快照。
- 本构建入口、缓存模块、原打包器、补丁模式/顺序、实际 Node 命令与堆上限。
- 已审核构建环境字段以及 `VITE_`、`PUBLIC_` 字段的摘要，不将其值写进回执或日志。

源实际路径和依赖安装根也参与身份，因此移动准备目录、变更 Node 或依赖内容会失效。
这是包含私有 source map 来源的同机本地复用，不承诺跨目录或跨机器命中。

检测到自动加载的 dotenv 文件时只检查存在性，不读取内容；配置不再匹配已审核配方、
新增未确认的环境读取/构建选项、Node/编译器注入环境、外部依赖链接或私密文件时，
日志明确输出 `frontend_cache_disabled`，不复用或生成缓存，仍执行正常构建。
运行时目录、用户数据、数据库、日志和凭证不属于扫描范围，不能为了命中扩大它。
这里的不读取是缓存采集器的边界；随后的正常 Vite 构建仍沿原机制加载其自身配置，不改变旧入口行为。

## 产物和失败恢复

产物继续由现有 `packageFrontendBuild` 生成：

- `frontend-build/`：仅公开资源，不含 `.map`，不覆盖官方 Pyodide。
- `frontend-build-manifest.json`：全部公开文件与原来源字段。
- `frontend-debug/`：私有映射与绑定公开清单的私有清单。
- `.dockerignore`：继续排除 `frontend-debug/`。

缓存回执在独立缓存目录，不复制到 `OUT`。命中须同时满足完整输入身份、来源、回执中的产物签名、
公开/私有清单绑定以及两类目录的完整文件集合和摘要。目录根、manifest、回执和子项中的链接均拒绝，
不能依赖外部路径补足缓存。恢复后再次核对输出，不以首页存在代替完整性。

只有本次加密产物校验和 Vite 真正成功，且构建前后输入身份一致，才创建新缓存回执。
前两批旧产物没有当时完整输入、依赖和环境回执，不能事后补认成缓存种子。
同一准备目录应串行构建；缓存采用新临时目录发布，不覆盖已存在条目，异常残留不自动删除。

损坏条目会明确失败，不自动重建或退回另一份旧产物。保留问题条目和可能产生的部分输出后：

1. 换一个新的 `OUT`，使用新的空 `--cache-dir`，生成新的证明；或者
2. 省略 `--cache-dir`，在新的 `OUT` 执行原正常构建。

不要覆盖旧输出，也不要通过手改回执摘要让损坏条目变成通过。需要清理本地缓存时，
先核对明确目标，不能递归清理源码、依赖安装树或旧发布产物。

## 检查和计时口径

定向合同入口：`node --test deploy/frontend-build-cache.test.mjs`。
覆盖旧/新模式、输入失效、dotenv 不读、路径/junction、规定根项链接、额外/缺失/损坏文件、
私有绑定与同模式自洽产物替换，测试不构建业务或调用服务器。

显式缓存用法在 JSON 结果中报告 `cache`、`built`、`cache_key` 和阶段 `timing`。
`cache_verify_restore_ms` 包含缓存公开/私有完整性核验、复制与恢复后核验，不能称作完整构建时间。
缓存命中的总耗时还必须包括完整输入审计；首次未命中另有构建后的输入复核和缓存发布成本。
真实对照使用产物缓存未命中构建与同源命中，不暗示操作系统、依赖下载或编译器缓存全部为冷。
本能力不需要重复业务浏览器验收；不包含上传、部署、CDN 操作、Docker 启动或真实模型调用。

首次未命中会比旧无缓存路径增加两轮全输入审计和缓存写入，不能把这段额外成本算进旧入口基线后
再宣传命中提速百分比。本轮不为凑基线额外重跑旧 Vite：分别报告 Vite 实际阶段、未命中额外成本
和命中完整校验/复制总时间。

适合启用缓存的情况是同一冻结源码、工具链和环境需要再次生成新交付目录。
只构建一次、每轮都会改源码/静态资源、经常移动准备目录或更换依赖时，优先继续旧入口，避免每次未命中
都多付审计与写入成本。摊平次数只能按这些阶段数据估算，不代表另一轮旧构建的实际耗时。

## 2026-11-03 本地实测

团队的游戏帧耗时和 API SQL/编译测量结束后，冻结三个生产文件，再执行一次有效的产物缓存未命中构建，
随后同源命中。没有重建旧无缓存入口，也没有重跑业务浏览器。

本次使用 Node `v22.14.0`、`FRONTEND_BUILD_HEAP_MB=6144` 和保留的第二批准备源码。
如需在同一台机器复用这份演示缓存，从仓库根目录执行下面的命令；输出目录仍必须是尚不存在的新目录。
Node、源码、依赖或其他有效环境变化都会按输入规则重新判定，不保证跨环境命中。

```powershell
$env:FRONTEND_BUILD_HEAP_MB = '6144'
node deploy/build-performance-frontend.mjs .build/frontend-bootstrap-20261103/source .build/frontend-cache-20261103/new-repeat-output bootstrap --cache-dir .build/frontend-cache-20261103/cache-final
```

| 阶段 | 产物缓存未命中 | 同源命中 |
| --- | ---: | ---: |
| 完整命令墙钟时间 | 179.617 s | 10.364 s |
| 完整输入身份审计 | 15.844 s | 6.062 s |
| 加密产物校验 | 0.067 s | 沿用已绑定证明 |
| Vite 进程阶段 | 140.264 s | 不运行 |
| 缓存核验、复制及恢复后核验 | 无现存条目 | 4.205 s |
| 构建后输入复核及缓存发布 | 21.088 s | 不执行 |

首次未命中的可单独计量缓存额外成本为 `15.844 + 21.088 = 36.932 s`。
其余约 `2.354 s` 为原有检查、打包等与命令启动开销的差额估算，没有伪装成独立实测阶段。
输入审计每次真实读取源码和实际安装依赖；本次依赖内容为 56,832 个文件、约 1.118 GB，
不使用文件时间快照取代内容核验。两次身份审计耗时不同，不代表操作系统文件缓存完全为冷。

不能用 `179.617 s` 当作旧入口基线计算提速百分比。若仅以本次 `140.264 s` 的 Vite 阶段作为
旧正常构建耗时的保守代理，并假设条件近似，同源再命中一次就足以抵消约 `36.932 s` 的首次额外成本；
这是分段估算，不是旧入口的重新实测或跨机器保证。只构建一次时，这些额外成本无法摊平，应使用旧入口。

命中恢复的 4,808 个公开文件和 838 个私有映射已完整核验；冷/热两份公开与私有清单逐字节一致，
公开清单也与第二批已验收产物一致。因此应用资源和运行行为未改变，无需为演示缓存重新试玩。
旧默认模式和 `bootstrap` 模式分别通过夹具恢复、错模式和完整性合同；真实未命中/命中测量使用 `bootstrap`。

记录位于本仓库的 `.build/frontend-cache-20261103/`：

- `cold-final.log`、`cold-final-wall.json`：有效未命中构建。
- `hit-final.log`、`hit-final-wall.json`：同源命中，`built=false`。
- `measurements.json`：阶段时间、清单一致性和计时边界。
- `cache-final/`：本次生成的输入/产物绑定回执；不进入发布输出。
- `cold-final/`、`hit-final/`：两份新交付输出，均不覆盖旧产物。

此前 `cold.log` 对应一个为合并新增已知 Docker 路径限制而中断的候选，只停止该次明确 PID 和 Node 子进程。
该记录保留但不纳入有效对照，没有将它算作成功构建、缓存种子或冷基线。22 项定向缓存合同测试通过；
未上传、部署、启动 Docker、调用真实模型、提交或推送。
